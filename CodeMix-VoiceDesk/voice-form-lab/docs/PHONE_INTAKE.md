# Telephone complaint intake

The application includes an inbound Twilio recording integration. It is disabled by default. No telephone account, number, paid calls, or public hosting are created by this project. Local automated tests use synthetic calls and mocked media/ML; they do not prove live telephone connectivity or telephone speech accuracy.

## Caller workflow

Callers choose 1 Tamil, 2 Telugu, 3 Kannada, 4 Malayalam, 5 English, 6 Hindi, or 7 automatic detection. They hear a recording disclosure, press 1 to consent (9 declines), and leave up to 60 seconds of speech, finishing with #. A numeric reference acknowledges intake, not a successfully processed or resolved complaint. Completed recording callbacks queue transcription, extraction, and a private case requiring staff review. Staff can inspect progress under **Phone intake**, then review the case normally.

Default spoken prompts are English. To localize the experience, set `PHONE_PROMPTS_BASE_URL` to an HTTPS directory containing operator-approved `menu.wav`, `consent-{language}.wav`, and `record-{language}.wav` for ta, te, kn, ml, en, hi, and auto. Consent recordings must disclose provider recording, processing, text retention, and the actual configured audio retention policy. Language menu options are not evidence of recognition quality; test consented speakers and telephone audio separately before deployment.

## Activation

1. Obtain an inbound voice-capable Twilio number supported for your intended callers. Check provider availability, account requirements, and charges directly with the provider.
2. Deploy the API behind a public HTTPS origin. Set `PHONE_PUBLIC_BASE_URL` to that exact origin, without a path or trailing slash. The proxy must preserve the `/api/phone/twilio/` paths. The local Compose address is insufficient for incoming provider callbacks.
3. In your private `.env`, configure `PHONE_ENABLED=true`, `PHONE_PUBLIC_NUMBER` in E.164 format, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` for signature verification, and `TWILIO_API_KEY_SID` / `TWILIO_API_KEY_SECRET` with recording read/delete permissions. Never commit these values or paste them into chat. Leave phone intake disabled until these exist. Existing demo login settings are separate.
4. Configure the number's incoming voice webhook to POST `https://YOUR-ORIGIN/api/phone/twilio/voice`. Other action/status callback URLs are generated by the application. Recreate the API with `docker compose up -d --build --wait`.
5. Make a real consented test call for every supported prompt/language path. Verify the reference, transcription, staff review, duplicate callbacks, rejection without consent, and provider recording deletion before publishing the number. Configuration alone does not verify a live line.

Webhook routes: POST `voice`, `language`, `consent`, `recorded`, and `recording-status` under `/api/phone/twilio/`. These require a valid provider signature even though they do not use staff login. Staff-only GET `/api/phone/status` and `/api/phone/intakes` use application authentication. OpenAPI describes these endpoints.

## Reliability and privacy

The SDK verifies signatures against the configured public origin and all form fields. Duplicate parameters and query strings are rejected. Caller `From` numbers are not persisted. Account/call/recording identifiers are private operational metadata; the staff list omits provider identifiers. Recording URLs supplied in callbacks are ignored: downloads use a fixed authenticated provider host, reject redirects, enforce a 5 MiB limit, and require WAV headers.

The fast webhook only acknowledges/queues work. Durable PostgreSQL jobs retry processing at most five times with increasing delays, recover expired processing leases, and expire incomplete calls after one hour. Repeated callbacks do not create duplicate cases, including after staff delete a case. Predictions and human corrections remain separate.

Provider audio is requested for deletion after successful processing or terminal failure; failures remain visible as pending cleanup and are retried. This is separate from application `RETAIN_AUDIO` (off by default). Temporary provider recording is necessary for this integration even when application audio retention is disabled. Monitor provider storage and cleanup; network or credential failures can delay deletion. No raw audio or secrets belong in application logs.

## Reproducible checks

Run `mvn -f api/pom.xml test` with Docker available: phone tests use Testcontainers PostgreSQL, synthetic signed callbacks, mocked recording media and mocked ML. They cover seven language selections, consent rejection, forged signatures, retry/recovery, callback replay, private endpoints, case deletion, and cleanup. `npm run e2e` from `web` checks the disabled phone desk against the running default stack. Live PSTN calls and localized recordings remain deployment acceptance checks.

Provider references: [recording callbacks](https://www.twilio.com/docs/voice/twiml/record), [webhook signatures](https://www.twilio.com/docs/usage/security), [recording media and deletion](https://www.twilio.com/docs/voice/api/recording).
